Independent acceptance

Choose how the finished candidate is compared with the original. Set this before starting the task; originals are never changed.

What this check supports

Use a static x86-64 or AArch64 ELF, or standard x64/ARM64 PE original and a JSON build manifest as the candidate path. Original and candidate may use different supported architectures. AArch64 uses base AAPCS64 with x18 reserved; floating-point arguments, aggregates, variadics and OS services are outside this call contract. Supply at least two cases. Buffers may be shared by multiple arguments. Every buffer is compared; undeclared imports, TLS, image-global writes and OS calls remain unsupported. Supplied DLL linking supports matching x64 or standard ARM64 PE modules; dependencies must not require loader initialization.

What this check supports

Use an x64 console PE executable as the original and a C build manifest as the candidate. Supports standard streams, fixed tick clocks, process exit, declared regular files, explicit command-line/environment queries and private virtual memory. File APIs include CreateFileA/W, ReadFile, WriteFile, CloseHandle, SetFilePointerEx, GetFileSizeEx, SetEndOfFile (truncation), DeleteFileA/W and GetLastError/SetLastError; process queries use GetCommandLineA/W and GetEnvironmentVariableA/W. VirtualAlloc, VirtualProtect and VirtualFree support private non-executable buffers with reserve/commit, read/write protection, decommit and release. Standard streams use synchronous redirected-file semantics. Unsupported APIs and faults fail the check. No Windows DLLs or native target execution are required.

What this check supports

Each case may supply files as a name-to-hexadecimal map, command_line as the exact observed Windows command-line string, and env as a name-to-value map. The default command line is program.exe and environment is empty; host settings are never inherited. Process values use bounded ASCII; environment names are case-insensitive. Files are private to that replay; all final files are compared. Use ordinary ASCII names in C:\work, without subdirectories. Files total at most 1 MB; only synchronous access with normal attributes and read/write sharing is supported. Virtual memory uses 4096-byte pages, at most 16 MiB cumulative reservations and 256 allocations; protection applies to CPU and API buffer access. New reservations require a null address. Directories, devices, overlapped I/O, executable memory and undefined file extension bytes are rejected.

What this check supports

Set architecture in the build manifest to x86_64 (default) or aarch64. Both architectures use unicorn_linux for streams, exit, explicit argv/env and fixed clock, or qiling_linux for declared file, directory, memory and random effects. Both architectures support dynamic ELF/PIE with an explicitly supplied matching interpreter and libraries. Architecture may differ between original and reconstruction.

What this check supports

Use the original ELF file above and the build manifest JSON as the candidate path. Inputs are sealed when the contract is pinned. For dynamic executables, supply the interpreter and every library, and set each case’s runtime to qiling_linux. Optional files map guest paths to hexadecimal contents. argv and env declare process inputs. Strict mode also matches application effect sequences and random consumption. Observable mode permits different library/allocation activity while checking streams, exit, input consumption, selected memory and final files/directories. Full traces are retained.

A passing check covers only its declared scope and inputs. Resume the task when the target and checks are ready.
