Independent acceptance
Choose a register, function or supported complete-program comparison before starting the task. Original bytes are preserved, and the candidate is checked independently on completion.
Use a linked ELF or PE original and a JSON build manifest as the candidate path. Supply at least two cases. Buffers may be shared by multiple arguments. Every buffer is compared; undeclared imports, TLS, image-global writes and OS calls remain unsupported. Supplied DLL dependencies must not require loader initialization.
Use the original ELF file above and the build manifest JSON as the candidate path. Inputs are sealed when the contract is pinned. For dynamic executables, supply the interpreter and every library, and set each case’s runtime to qiling_linux. Optional files map guest paths to hexadecimal contents. argv and env declare process inputs. Strict mode also matches application effect sequences and random consumption. Observable mode permits different library/allocation activity while checking streams, exit, input consumption, selected memory and final files/directories. Full traces are retained.
Scalar function checks compile self-contained C and compare protected integer inputs. Linked-call checks also support declared pointer buffers. Program checks use the selected Linux runtime and explicit process inputs. Register and function checks cover their declared scope. Complete-program checks cover the pinned inputs and supported runtime effects. Resume the task when the target and checks are ready.
